## 二、怎么用

### 玩家

1. 出战页点「🤖 第五代人机」按钮，四态循环：**关闭 → 敌方 → 队友 → 双方**
2. 出战页点「🧪 第六代人机」按钮，四态循环：**关闭 → 敌方 → 队友 → 双方**
   （第六代 PPO=确定性推理、静态权重；与第五代同开时同辆车先到先得）
3. 战斗中按 **Q「AI 代打」**：大脑换成学习型（2026-10-04 起）——
   出战页「🎮 Q 代打」按钮选**第六代（默认，会走位/自保/脱困）或第五代（带避让绕路）**，
   切换后下次按 Q 生效；Q 开关/代打 buff/HUD 沿用游戏原版；飞机/直升机局仍原版；
   `?bcQ=0` 可整体还原
4. 开始战斗：
   - **敌方**：红方全部坦克换成 BC bot
   - **队友**：己方 AI 队友换成 BC bot（角标显示 `🤖 BC[队友]`）
5. 战场右上角角标实时显示：bot 数 / 开火数 / 🧯灭火次数 / 🔧修理秒数
6. URL 参数（调试）：`?bc=1`（敌方）、`?bc=ally`（队友）、`?bc=0`（强制关）、
   `?bcAssist=0`（关开火兜底）；`?rl=1 / ?rl=ally`（第六代训练/评测入口）

### 开发者（重训流程）

```bash
cd app/games/warthunder-game
python3 -m http.server 8000 &                       # 起服务器

# 1. 采规则 AI 原始数据（无头农场，全自动）
electron training/farm-record.cjs 60000 4 training/data 8000

# 2. 采 DAgger 纠正数据（BC 开车+影子老师纠错）
electron training/farm-dagger.cjs 30000 4 training/data-dagger 8000

# 3. 混合训练（numpy 手写 MLP，无需 torch）
python3 training/bc_train.py 40

# 4. 评测（BC 队友 vs 规则队友，各 N 局）
electron training/eval-bc.cjs 3 4 8000

# 5. 权重已直接生效：training/bc-weights.json（游戏 fetch 加载）
```

单轮成本参考：采集 3 万样本 ≈ 6 分钟（4 无头窗口，~85 样本/秒）；
训练 40 epoch ≈ 2 分钟（纯 numpy）。

## 三、技术架构

### 观测 / 动作空间（与录制端逐位一致，`js/agent-core.js` 单源共享）

```
obs（70 维定长）                          act（5 维）
├─ 自身 16：朝向/炮口角 sin·cos、俯仰、   ├─ throttle  [-1,1]
│  血量、装填、canFire、本体系速度、        ├─ turn      [-1,1]
│  位置、模块损伤×3、起火                  ├─ aimYaw    [-1,1]×π（相对车体方位）
├─ 最近 3 敌 ×11：距离/方位/速度/         ├─ aimPitch  [-1,1]×0.3rad
│  炮口指向/血量/穿深/装甲                 └─ fire      [0,1]
├─ 最近 6 障碍 ×3：距离/方位
└─ 上下文 3：边界余量、LOS 遮挡、局时
```

### 网络

MLP `70 → 256 → 256 → 5`（ReLU；前 4 维 tanh 回归 + 第 5 维加权 BCE），
**约 8.5 万参数**，权重 json 1.8MB。训练：纯 numpy 手写前向/反向 + Adam（`bc_train.py`）。
推理：浏览器手写 JS 前向（`agent-core.js makeMLP`），零依赖零体积开销。

### 部署形态（第五代混合架构）

```
TankAI.update 被替换为 bcPilotUpdate：
  ├─ 维护层   🧯灭火 + 🔧修车（每帧）
  ├─ 远距(>270m)  P 控制器进场（朝最近敌）
  └─ 交战区   BC 网络驾驶 + 几何炮手 + 开火(网络∪纪律兜底)
任何异常 → 回退原规则 AI（保留原 update 引用，每 tank 独立）
```

（Q 代打接管默认开，仅替换 _pilotAI.update，异常自动回退原版 TankAI）。

## 五、踩坑记录（工程财富）

1. **因果颠倒（最关键）**：录制时 obs 在 100ms 窗口末采样，开炮引发的装填重置
   已写入同条样本 → 网络学到「装填没好才开炮」，实战 fire 概率 1e-14。
   *教训：模仿学习的 (obs, act) 配对必须保证 obs 是动作发生前的状态。*
2. **BC 复合误差**：转向回归把「左转/右转」双峰平均成直行，bot 进不了场
   （敌距恒 450m+）。解法：部署端远距 P 控制器 + DAgger 迭代。
3. **网络瞄准精度不足**：aimYaw MAE 0.044（≈8°），百米外弹着点偏 10m+，
   杀敌效率减半。解法：几何直瞄替换（保留网络头待 PPO 用）。
4. **评测指标饱和**：第一版评测（敌方 BC vs 挂机玩家方）每局 6:0 全灭零差异，
   全部指标饱和无区分度。解法：改为「BC 当队友」对照评测，用时/存活有区分。
5. **稀疏标签**：开火样本仅 0.5%，且规则 AI 开火含 `Math.random()` 不可学噪声，
   fire 头 F1 天花板 ~0.4。解法：BCE 正类加权 + 过采样 + 部署端纪律兜底。
6. **PPO 首更雪崩**（第六代）：value 头随机初始化 + 与策略共享 trunk → 首个 update
   value 巨梯度把 BC 热启动的驾驶头拖飞（KL 1.29 / pclip 96%）。解法：首批纯 value 预热拟合
   （冻结 policy 列）+ LR 3e-4→1e-4 + 每 epoch KL>0.05 早停 → KL 0.13 / pclip 15%。
7. **脚本壳与采样的边界**：远距 P 控制器是脚本驾驶，那段发生的命中/挨打不能归给策略
   （动作不是它出的）——采样与奖励都按交战区门控，导航段事件直接丢弃。
8. **炮手没有提前量是隐性吃亏**：规则 TankAI 自带迭代解拦截+下坠补偿，几何直瞄没有；
   近战 22~46m 影响小（所以第五代总分能追平），但 100m+ 打横移目标必偏。解法：core 层
   gunAimPoint 共享，BC/RL 双侧同款。注意游戏给敌方炮弹硬编码 0.032 弧度散布——
   命中率天花板由规则平衡决定，炮手只能保证弹着中心在目标上。
9. **跨语言 JSON 的 NaN 陷阱**：Python `json.dumps` 默认把 NaN 写成裸标识符（非法 JSON），
   JS `JSON.parse` 直接抛异常——训练服务器 /stats 首更前全是 NaN，农场误判"服务器不可达"
   连退两次。教训：跨语言接口里 NaN 一律转 null（`allow_nan` 语义差异）。
10. **日志时区乌龙**：JS `toISOString()` 是 UTC，本地 +8——把正常跑了 29 分钟的训练场
    误判成"8.5 小时僵尸农场"。教训：跨组件对时先统一时区口径，或时间戳全用本地 + 标注。
11. **PPO 首训步数不足 + 末期过急**（10-04）：40 分钟 / 10.2 万步，mean_rew 只从 −0.04 爬到
    −0.008 未出噪声区；末期 KL 冲 0.27 说明单次更新迈太大。结论：从 BC 热启动追平自身
    需要百万步级；下轮 LR 再降 / 训练时长 2~4 小时 / **checkpoint 滚动备份**（本轮只存
    latest，想回滚中途较好版本时发现无版本可回）。
13. **部署壳必须与训练壳严格一致**（10-04 六代 311s 事故）：训练结束后给外壳加避让层，
    部署的策略没见过这层外力→执行动作偏离采样动作→进场均被拽偏（局时长 201→311s，
    出现 422/526s 拖尾）。撤除即复原。教训：**改外壳=改环境，改完必须重训或至少复测**；
    RL 部署件要冻结训练时同款外壳。第七代起避让层入训练壳同训（治本）。
14. **ES 模块「同一实例」铁律的 cache-buster 变种**（10-05 五/六代集体 202→520s 事故）：
    lib.js 的 terrainMode/terrainScale 是**模块级状态**（main.js 开局用自己 import 的实例
    setTerrainMode 设置）。给 import 重试加 `?r=1` 防"毒缓存"→URL 变化=浏览器实例化**另一个
    模块**→智能体侧 terrainHeight 用默认地形参数算高度→地形 LOS 大规模误拦开火。
    症状特征：terrainHold 计数异常暴涨（1 万+帧 vs 正常 ~2500 帧）、且只打学习型 bot
    （规则 AI 走游戏内自己的地形检查不受影响）→ 同代 bot 集体变慢而规则正常。
    教训：**给带状态的共享模块做 import 重试必须原 URL**（失败的动态 import 不会被
    memoize，同 URL 可重试）；改"理论无害"的代码也要按"改环境"对待——先冒烟复测。
15. **长训/评测的宿主环境三坑**（10-05）：① macOS 无 timeout 命令；② shell 工具超时杀
    进程组会 SIGTERM 波及 nohup 后台任务（要 `& disown` 且日志落盘）；③ **系统睡眠冻结
    一切**（150 分钟训练被冻在 116 分钟、唤醒后 http.server socket 半死、farm 计时器错乱）——
    长任务前 `caffeinate -is` 防睡，唤醒后重启静态服务器与探活。
16. **BC 火头的 logit 不能直接当伯努利探索分布**（10-05 七代）：稀疏正例（1.1%）+ pos_weight=20
    训出来的 fire logit 极端负（mean −27 / p50 −15.7 / p5 −83），固定偏置无法校准这种方差。
    解法：**对数尺度温度** q=sigmoid(0.12·f+0.6)——中位状态→0.22、好状态→0.58、差状态→≈0，
    采样与 logp/熵同口径（PPO ratio 自洽），梯度照常流经 f；部署不带温度（保守）+纪律兜底。
    另：训练时纪律兜底必须关——环境替策略开火命中会把正优势推给 fire=0 样本（反向教学）。
12. **开火门的两个隐形漏洞**（10-04 用户实战反馈）：①视线检查只查障碍物（房子/石头）
    不查地形——敌在坡下时炮弹全喂山；②收敛判定只查水平角 yaw——行进间悬挂颠簸+
    车体摆动让炮管俯仰/世界指向偏掉，yaw 过门照样打飞。解法：`terrainLos`（动态 import
    lib.js 拿**同一模块实例**的 terrainHeight，terrainMode/Scale 状态与 main.js 天然同步，
    弹道线段 8 点采样 vs 地形高度+0.4m 余量）+ `barrelAligned`（getBarrelDir 与瞄准点的
    3D 夹角 <0.04rad）。教训：**判定口径要与物理发射口径一致**——游戏按炮管真实指向
    发射（getBarrelDir + spread），那就按它验收，而不是按自己记录的 turretYaw。
